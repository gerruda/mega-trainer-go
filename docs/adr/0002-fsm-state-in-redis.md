# ADR-0002. Состояние диалогов — в Redis

**Статус:** принято
**Дата:** 2026-10-28

## Контекст

Бот ведёт пошаговые диалоги (`/water`, `/onerepmax`, `/bodyfat`, `/tdee`,
`/measure`) и должен помнить, на каком шаге пользователь и что уже ввёл.
В исходной версии состояние лежало в Redis, но тип состояния дублировался,
а данные шага могли потеряться при переходе.

## Решение

- Состояние — `domain.UserState{UserID, Command, Step, Data map[string]string}`.
- Хранение — Redis, ключ `mega-trainer:user_state:<user_id>`, TTL 24 часа.
- `StateService` предоставляет операции `Start / SetStep / SetData / Finish`.
  `SetStep` сохраняет собранные данные (главный исправленный баг).
- Обновления одного пользователя сериализуются keyed-lock'ом в транспортном слое,
  поэтому чтение-изменение-запись не пересекается.

## Рассмотренные альтернативы

| Вариант | Почему нет |
|---|---|
| Состояние в памяти процесса | теряется при рестарте/деплое, не работает при >1 инстансе |
| Состояние в PostgreSQL | избыточно: запись на каждый шаг, нужен TTL/чистка |
| Встроенный FSM-фреймворк | лишняя зависимость для 4 диалогов |

## Последствия

- Рестарт бота не ломает диалог пользователя.
- Забытые диалоги сами истекают через сутки.
- Данные шага — строки; парсинг и валидация выполняются в момент использования.
