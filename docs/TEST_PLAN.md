# TEST PLAN — Mega Trainer Bot

Документ для регрессии и приёмки. Каждый кейс имеет ID, предусловие, шаги и
ожидаемый результат. Колонка «Авто» показывает, покрыт ли кейс автотестом:
`unit` — юнит-тест, `—` — только ручная проверка.

## 1. Уровни тестирования

| Уровень | Что проверяет | Где |
|---|---|---|
| Unit | формулы, валидация, FSM-переходы, конфиг, cron, прокси-транспорт | `go test ./...` |
| Integration | репозитории на живой PostgreSQL, миграции | план: testcontainers-go |
| E2E / manual | реальный бот в Telegram, Docker-стек | чек-лист ниже |

Запуск: `make test` (с `-race`), покрытие: `make cover`.

## 6. Инфраструктура и отказоустойчивость

| ID | Кейс | Ожидание |
|---|---|---|
| INF-01 | Пустой `.env` | все проблемы конфига в одном сообщении, exit ≠ 0 |
| INF-02 | PostgreSQL недоступен | понятная ошибка, без паники |
| INF-03 | Нет прокси при блокировке Telegram | подсказка про `TELEGRAM_PROXY_URL` |
| INF-04 | Активный webhook у токена | при старте удаляется, polling работает |
| INF-05 | `SIGTERM` во время работы | graceful shutdown, воркеры дожидаются |
| INF-06 | `make migrate-up` дважды | идемпотентно, «no pending migrations» |
| INF-07 | Одновременный запуск двух migrate | advisory lock, второй ждёт |
| INF-08 | `make backup` | gzip-дамп в `./backups`, ротация старых |

## 7. Безопасность

| ID | Кейс | Ожидание |
|---|---|---|
| SEC-01 | Секреты в репозитории | отсутствуют (проверка `git log -S`) |
| SEC-02 | Логи | без токена, пароля БД и креденшелов прокси |
| SEC-03 | Конфиг с битым `proxy_url` | ошибка валидации при старте |
| SEC-04 | Docker-образ | запуск не от root, есть HEALTHCHECK |

## 8. Приёмка

Релиз считается готовым, если:

1. `make lint`, `make test`, `make build` — зелёные.
2. Все кейсы разделов 2–4 автоматизированы и проходят.
3. E2E-01…E2E-08 пройдены на реальном боте.
4. Нет открытых P0/P1 из [`docs/AUDIT_AND_PLAN.md`](AUDIT_AND_PLAN.md).
